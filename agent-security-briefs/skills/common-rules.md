# 通用规则

本文件是所有身份 skill 的共同约束。回答产品问题前先遵守本文件，再进入具体身份 skill。

## 基本铁律

1. 不编造产品功能、交付时间、客户案例、认证资质、竞品结论。
2. 先读 `_index/folder-routing.md` 判断产品目录，再按身份读取对应 brief。
3. `skills/` 目录只提供工作流程，不是产品事实来源。
4. brief 里没有的信息，先查对应产品的 `原始文档/`。
5. 原始文档也没有时，明确说“目前资料未覆盖”，并记入 `qa-log.md`。
6. 空模板产品只能按现有资料回答，不得补全未确认能力。
7. 竞品结论如果不是 brief 明确写出的，需要标注为推断。

## 确认产品

先确认用户在问哪个产品。无法判断时，先读 `_index/folder-routing.md`；仍无法判断时，只问一句：“这个问题是面向哪个产品？”

常用产品目录：

| 产品 | 目录 |
|---|---|
| 智能体身份安全 | `1-智能体身份安全/` |
| AI-BOM | `3-AI-BOM/` |
| 智能体安全 | `2-智能体安全/` |
| 智能体安全网关 | `4-智能体安全网关/` |
| ANS | `5-ANS/` |
| 海外版 | `海外版/` |

## 资料读取顺序

1. 先读 `_index/folder-routing.md`，确认应该进入哪个产品文件夹。
2. 再读对应产品的 `overview.md`。
3. 根据身份 skill 读取 `sales-brief.md`、`market-brief.md` 或 `architecture-brief.md`。
4. 跨产品问题读 `0-产品全景/product-map.md`。
5. 术语问题读 `0-产品全景/glossary.md`。
6. 竞品问题读 `shared/competitor-brief.md`。
7. 热点匹配读 `shared/hot-event-playbook.md`。

## 未命中记录

答不上来时，在 `qa-log.md` 表格末尾追加：

```md
| 日期 | 角色 | 产品 | 问题原文 | 原因 |
```

日期格式使用当天日期，如 `2026-07-07`。

原因从这些值里选：`brief缺失`、`brief不足`、`原始文档也没有`、`竞品信息缺`、`术语缺`、`市场热点缺`。

## 推断项

brief 直接写出的内容不是推断。AI 根据材料自行延伸出的结论是推断，需要标注。

回答末尾保留简短来源说明：

```md
---
读取文件：...
推断项：无 / 有
已记入 qa-log：否 / 是
```
