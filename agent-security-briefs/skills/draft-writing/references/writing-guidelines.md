# 写作规范参考（draft-writing）

## 1. 信息分层

| 层 | 内容 | 来源 |
|---|---|---|
| 事件层 | 新闻事件本身 | 待生成文章/事件输入 |
| 产品层 | 产品如何回应事件 | overview.md |
| 市场层 | 传播角度、金句、行业意义 | market-brief.md |
| 售前层 | 卖点、客户价值 | sales-brief.md（optional） |

## 2. 结构约束

1. 标题：新闻钩子在前，产品角度在后。
2. 导语 ≤ 120 字：事件一句话 + 关联点。
3. 正文按「背景 → 产品视角 → 市场价值 → 结语」推进。
4. 每个论点必须可溯源到知识文件；无来源的论点不写。

## 3. 语言要求

- 中文，书面语。
- 技术术语第一次出现时给出简短解释。
- 避免空泛套话（如「赋能」「引领」无实据的表述）。

## 4. 禁用表述

- 编造的具体数字、客户名、合作方。
- 未确认的交付时间、版本号。
- 绝对化断言（「唯一」「最好」）除非知识文件明确支持。
- 直接贬损竞品的措辞。
