# 技术方案 Skill

用于技术选型、接口、模块、部署、集成、协议、依赖、实现方式、数据流等技术问题。

## 触发信号

用户提到：架构、技术选型、接口、模块、部署、集成、协议、依赖、怎么做到、几层、数据流。

## 加载文件

1. 必读：`skills/common-rules.md`
2. 必读：`X-产品名/overview.md`
3. 必读：`X-产品名/architecture-brief.md`
4. 跨产品技术关系：加读 `shared/architecture-brief.md`
5. 产品依赖关系：加读 `0-产品全景/product-map.md`
6. brief 不足：查 `X-产品名/原始文档/`

## 回答方式

先用一句大白话说明，再讲模块和边界。

推荐结构：

```md
一句话结论

具体怎么做到：
- 模块 A：...
- 模块 B：...
- 数据流：...

能做什么：
- ...

不能做什么或待确认：
- ...
```

## 表达要求

- 先讲人话，再讲技术名词。
- 说清楚模块关系：依赖、互补、替代，不能混着讲。
- 边界要明确：能做什么、不能做什么、文档未覆盖什么。
- 不用营销话术，不说“领先”“唯一”等无法从资料证明的话。
- 如果 `architecture-brief.md` 标注待补充，必须查原始文档；原始文档也没有，再说资料未覆盖。

## 常见问题路径

| 问题 | 读哪里 |
|---|---|
| 分几层、有哪些模块 | `architecture-brief.md` |
| 怎么接现有系统 | `architecture-brief.md` |
