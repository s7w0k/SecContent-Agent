# 智能体安全网关

## 一句话定位

智能体调用链路中模型、工具和业务系统访问的统一入口与运行时控制点，用于在调用过程中执行安全策略、监测风险并联动阻断。

## 解决什么问题

- 企业同时接入多个模型、智能体和 MCP/工具时，缺少统一的调用入口、审计节点和安全策略执行点。
- 提示词注入、越狱攻击、MCP/工具调用劫持或投毒等风险，容易在调用链路中扩散。
- 高危工具调用、敏感数据输入输出和违规内容输出，需要在运行时进行检测、处置和留痕。

## 目标用户

- 需要统一管控模型与工具调用入口的企业 AI 平台、安全团队和运维团队。
- 需要对智能体调用链路做审计、拦截和合规管控的业务系统负责人。

以上目标用户为基于产品全景、技术架构和 ANS 原始文档的场景推导，具体行业、角色和采购对象仍需产品确认。

## 已确认能力边界

- 统一入口：产品全景和整体技术架构均将网关描述为智能体安全体系中的统一调用入口。
- 运行时控制：整体技术架构提到网关承担实时鉴权、限流/降级等能力。
- 风险防护方向：`5-ANS/原始文档/ANS.md` 提到提示词注入与越狱防护、MCP/工具调用风险控制、敏感数据防护和全链审计；这些内容属于原始售前材料提及，具体交付范围仍需产品确认。
- 联动关系：智能体安全中的告警响应可联动 AI 安全网关阻断；身份安全负责身份与权限，网关负责在入口处执行控制。

## 跟其他产品的关系

- 与智能体身份安全：身份安全负责认证、授权、意图和审计等策略基础，网关在调用入口执行实时控制。
- 与智能体安全：智能体安全负责行为分析、风险检测和告警响应，网关可作为阻断与处置执行点。
- 与 AI-BOM：AI-BOM 提供智能体、模型、工具和 API 等资产发现与台账能力；网关是否消费这些资产信息执行入口管控，当前资料未覆盖，需产品确认。
- 与 ANS：ANS 作为编排总控层，向下统一调度或编排网关、身份、安全、AI-BOM 等能力。
