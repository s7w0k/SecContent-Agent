# 智能体安全产品速查

本目录是公司智能体安全产品线的 AI 可读知识库。回答产品问题时，先用本文件做路由，再按身份读取对应 skill 和产品资料。

## 目录结构

```text
_index/                          <- 文件夹路由、产品索引、摘要索引
CLAUDE.md                        <- 入口与路由
AGENTS.md                        <- 给不识别 CLAUDE.md 的 AI 工具看的入口副本
qa-log.md                        <- 未命中问题日志
skills/                          <- 身份工作流，只写怎么答，不写产品事实
0-产品全景/                       <- 产品矩阵、关系图、术语表
1-智能体身份安全/                  <- 产品资料
2-智能体安全/                      <- 空模板，待补充
3-AI-BOM/                        <- 产品资料
4-智能体安全网关/                  <- 空模板，待补充
5-ANS/                           <- 空模板，待补充
海外版/                           <- 海外版产品组合
shared/                           <- 竞品、技术总图、热点匹配
```

`skills/` 目录只放回答流程，不作为产品事实来源。产品事实必须来自产品目录、`shared/`、`0-产品全景/` 或 `原始文档/`。

## 先读规则

每次回答前：

1. 确认用户在问哪个产品。
2. 判断用户身份：售前、技术方案、市场 PR。
3. 读取 `_index/folder-routing.md`，选择 1-2 个需要进入的文件夹。
4. 读取 `skills/common-rules.md`。
5. 读取对应身份 skill。
6. 读取对应产品的 `overview.md`。
7. 按 skill 要求读取其他 brief。

读文件时必须使用完整相对路径，例如 `1-智能体身份安全/overview.md`，不要只写文件名。

## 身份路由

| 身份 | 触发信号 | 读取 skill |
|---|---|---|
| 售前 | 客户、打单、方案、对比、优势、卖点、报价、部署周期、能不能、有没有案例、多少钱 | `skills/presales.md` |
| 技术方案 | 架构、技术选型、接口、模块、部署、集成、协议、依赖、怎么做到、几层、数据流 | `skills/architect.md` |
| 市场 PR | PR、热点、传播、金句、媒体、新闻、公众号、舆情、能蹭吗、角度、标题、稿件 | `skills/market-pr.md` |

如果一句话里同时出现多个身份信号，以第一个明确出现的身份为准。无法判断时，只问一句：“这个问题是面向客户、技术方案还是市场传播？”

## 产品资料规范

每个产品目录推荐包含：

| 文件 | 作用 |
|---|---|
| `overview.md` | 产品简介、定位、核心能力、适用场景 |
| `sales-brief.md` | 售前卖点、竞品、FAQ |
| `market-brief.md` | 热点、金句、传播角度、PR 素材 |
| `architecture-brief.md` | 技术模块、部署、接口、边界 |
| `tasks.md` | 状态、计划、暂不做 |
| `原始文档/` | 完整 PRD/PPT/原始资料，brief 不足时兜底 |

## 通用问题路径

| 问题类型 | 读取路径 |
|---|---|
| 不确定读哪个文件夹 | `_index/folder-routing.md` |
| 跨产品关系 | `0-产品全景/product-map.md` |
| 术语解释 | `0-产品全景/glossary.md` |
| 竞品对比 | `shared/competitor-brief.md` + 产品 `sales-brief.md` |
| 热点匹配 | `shared/hot-event-playbook.md` + 产品 `market-brief.md` |
| 技术总图 | `shared/architecture-brief.md` |

## 兜底规则

- brief 没有的信息，先查对应产品的 `原始文档/`。
- 原始文档也没有，诚实说“目前资料未覆盖”，并记入 `qa-log.md`。
- 任何推断都要标注为推断。
- 空模板产品只能基于现有资料回答，不得补充未确认能力。

## 汇报格式

回答末尾保留简短来源说明：

```md
---
读取文件：...
推断项：无 / 有
已记入 qa-log：否 / 是
```
