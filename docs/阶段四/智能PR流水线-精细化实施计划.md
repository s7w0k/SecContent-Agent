## 1. 需求概述与目标

### 1.1 核心流程

```
入库文章
    │
    ▼
[LLM 6分类]
    ├── 爆点事件 ──────────┐
    ├── 法律法规/监管动态 ──┤
    ├── AI技术重大进展 ────┤  ← 进入 PR 流程
    ├── 国内外竞品信息      │
    ├── 运营商/行业事件     │  ← 不入 PR，仅展示
    └── 学术/会展/高校      │
                           │
                    ┌──────┘
                    ▼
              [双维度打分]
              ├─ 产品能力相关度 (0-100)
              └─ 影响面与传播力 (0-100)
                    │
            总分 ≥ 80 ──→ [PR模板匹配] → 4篇PR草稿
```

### 1.2 交付物

| # | 交付物 | 路径 | 说明 |
|---|--------|------|------|
| D1 | 6分类 LLM Agent | `agent/classifier_v2.py` | 替代现有2分类，支持6类别 |
| D2 | 双维度打分 Agent | `agent/scorer_v2.py` | 产品相关度 + 影响传播力 |
| D3 | PR模板库 | `agent/pr_templates.py` | 3类 × 多套模板 |
| D4 | PR草稿生成器 | `agent/draft_generator.py` | 每篇高分文章生成4篇草稿 |
| D5 | 流水线编排 | `agent/pipeline_v2.py` | 分类→筛选→打分→草稿 |
| D6 | 前后端联调 | API + Dashboard 更新 | 新流程可视化 |

## 3. 分类体系设计

### 3.1 六分类定义

| 类别 | 关键词 | 定义 | 是否进入PR |
|------|--------|------|-----------|
| **爆点事件** | 漏洞披露、APT攻击、0day、勒索、数据泄露 | 突发性重大安全事件，引起行业广泛关注 | ✅ |
| **法律法规/监管动态** | GDPR、网络安全法、数据安全法、等保、合规 | 国内外法规更新、监管政策、合规要求 | ✅ |
| **AI技术重大进展** | LLM突破、Agent框架、MCP协议、模型发布 | AI/Agent 安全领域的技术里程碑事件 | ✅ |
| 国内外竞品信息 | 友商产品发布、融资、合作 | 竞品动态，用于市场情报 | ❌ |
| 运营商/行业事件 | 移动/电信/联通、金融/能源/政务 | 重点行业的安全事件或采购动态 | ❌ |
| 学术/会展/高校 | 论文发表、会议、高校合作 | 学术前沿、产学研动态 | ❌ |

### 3.2 Classification Prompt

```
你是一个安全情报分析师。请阅读文章内容，将其归入以下6类之一：
1. 爆点事件 — 重大漏洞/攻击/数据泄露等突发安全事件
2. 法律法规/监管动态 — 国内外安全法规、合规政策更新
3. AI技术的重大进展 — AI/Agent安全领域技术突破
4. 国内外竞品信息 — 友商产品、融资、合作动态
5. 运营商行业/其他重点行业事件 — 电信/金融/能源等行业安全事件
6. 学术/研究组织/会展/高校信息 — 论文、会议、产学研

返回JSON: {"category": "类别名", "confidence": 0-100, "reason": "20字理由"}
```

## 4. 打分体系设计

### 4.1 双维度定义

#### 维度一：产品能力相关度 (0-100)

评估"这个事件和我们产品的关系"：

| 分数 | 标准 |
|------|------|
| 90-100 | 直接涉及产品核心能力（身份安全、Agent安全、MCP协议），产品能直接解决/参与 |
| 70-89 | 与产品能力有明确交集，可作为典型案例或营销素材 |
| 50-69 | 泛安全/泛AI事件，产品能部分关联 |
| 30-49 | 弱关联，仅作行业背景 |
| 0-29 | 与产品无关 |

#### 维度二：事件影响面与传播力 (0-100)

评估"这个事件本身有多大的话题价值"：

| 分数 | 标准 |
|------|------|
| 90-100 | 全球性/国家级重大事件，主流媒体广泛报道，行业标杆意义 |
| 70-89 | 行业内有较大影响，安全圈热传，可引发客户关注 |
| 50-69 | 细分领域有影响力，专业媒体覆盖 |
| 30-49 | 一般性报道，有一定参考价值 |
| 0-29 | 常规动态，无显著传播力 |

### 4.2 Scoring Prompt

```
## 产品知识库
{knowledge_context}

## 文章内容
标题: {title}
来源: {source}
正文: {content}

## 评分任务
从以下两个维度评分（各0-100）：

1. 产品能力相关度：这个事件与我们的产品有关吗？产品能解决它吗？能蹭这个热点吗？
2. 事件影响面与传播力：这事到底有多大？是我们蹭它，还是找论据？

综合分 = 产品能力相关度 + 事件影响面与传播力

返回JSON: {"product_relevance": 85, "event_impact": 70, "reason": "40字理由"}
```

### 4.3 阈值

- 综合分 ≥ **80** → 进入 PR 草稿生成
- 综合分 < 80 → 仅保存评分，不生成草稿

## 5. PR 报道生成设计

### 5.1 PR 模板库

按3个PR类别设计模板，每类至少2套：

#### 爆点事件模板 (2套)

```
模板A — 事件速报型:
# [事件名称]：影响分析与产品应对建议

## 事件概述
[2-3句概述事件基本信息：时间、涉及方、事件性质]

## 技术分析
[事件的技术原理、攻击路径或漏洞机制]

## 产品关联
[我们的产品如何应对/检测/防护此类事件]

## 市场机会
[可作为销售话术、客户沟通素材的要点]

## 行动建议
[产品侧/销售侧/市场侧的具体行动项]

---

模板B — 深度解读型:
# 深度解读：[事件名称]背后的安全趋势

## 事件还原
[详细还原事件经过]

## 根因分析
[深入分析根本原因]

## 行业影响
[对行业格局、标准、监管的潜在影响]

## 我们的机会
[产品/方案的切入点]

## 推荐策略
[短期+中期+长期策略]
```

#### 法律法规模板 (2套)
#### AI技术重大进展模板 (2套)

### 5.2 草稿生成流程

```
高分文章 (综合分 ≥ 80)
    │
    ├── 匹配PR模板（按分类选2套模板）
    │
    ├── LLM生成 × 2套模板 = 4篇草稿
    │   ├── 模板A → 草稿1
    │   ├── 模板A → 草稿2（不同角度）
    │   ├── 模板B → 草稿3
    │   └── 模板B → 草稿4（不同角度）
    │
    └── 保存到 Article.pr_drafts
        [{template: "爆点A", content: "..."}, ...]
```

## 8. 验收标准

### 8.1 功能验收

- [ ] 文章入库后自动触发6分类（或手动触发）
- [ ] 6分类标签在 Dashboard 以不同颜色展示
- [ ] 仅3类（爆点/法规/AI进展）进入后续 PR 流程
- [ ] 双维度打分（产品相关度 + 影响传播力）正常展示
- [ ] 综合分 ≥80 的文章生成4篇 PR 草稿
- [ ] PR 草稿可在前端查看

### 8.2 质量验收

- [ ] 分类准确率 ≥ 80%（人工抽检 20 篇）
- [ ] 打分合理（同文章两次打分偏差 ≤ 15 分）
- [ ] PR 草稿符合模板结构，内容可读
- [ ] LLM 调用超时降级不阻塞流程

### 8.3 技术验收

- [ ] 新增代码测试覆盖率 ≥ 80%
- [ ] 不影响现有 V1 流水线功能
- [ ] Docker 构建正常，一键启动

## 附录 A：与现有 V1 流水线的关系

```
V1 流水线（保留）：
  crawl → classify(2类) → score → report

V2 流水线（新增）：
  crawl → classify_v2(6类) → filter(3类) → score_v2 → draft(4篇)

两者共存，通过不同 API 端点调用。
```

## 附录 B：风险与缓解

| 风险 | 缓解 |
|------|------|
| LLM 分类不稳定 | 三次调用取多数，降级为默认类 |
| PR 草稿质量差 | 人工审核后回写 Prompt，迭代优化 |
| 知识库更新不及时 | 热加载 + 文件变更检测 |
