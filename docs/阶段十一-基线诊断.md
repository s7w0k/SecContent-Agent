## 热点排行现状与证据

当前请求为 `GET /api/articles/hot?limit=10&category=all&date_range=7d`，响应约定为：

```json
{
  "ok": true,
  "data": {
    "items": [],
    "total": 0
  }
}
```

代码诊断发现两个能够直接造成“有文章但热点为空”的数据兼容风险：

1. 热点接口只查询并排序 `pr_total_score > 0`；文章列表和统计接口仍以 `ai_relevance_score + reportability_score` 计算综合分。缺少 `pr_total_score` 的历史文章会被热点接口完全排除。
2. `7d` 等时间范围使用 BSON `datetime` 作为 `$gte` 条件。如果历史 `added_at` 是 ISO 字符串，MongoDB 不会把它按日期参与这个范围比较。

前端还会把热点请求异常直接转换为空数组，因此服务端异常与真实空结果在页面上表现相同。以上问题将在 11.6 修复；11.0 只记录现状，不提前改变行为。

只读数据诊断脚本会输出：

- `pr_total_score` 存在/正数覆盖率；
- 两项旧评分之和为正、但没有可用 `pr_total_score` 的文章数；
- `added_at` 的 BSON 类型分布；
- `category_v2` 分布；
- 当前热点过滤规则在 `1d/7d/30d/all` 下的命中数。
