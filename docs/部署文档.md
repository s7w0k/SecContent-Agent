# PR Agent Demo - 部署文档

## 环境要求

- **Docker** ≥ 24.0 + **Docker Compose** ≥ 2.20
- **磁盘**: ≥ 10 GB 可用空间
- **内存**: ≥ 8 GB
- **网络**: 可访问 DeepSeek API（`api.deepseek.com`）

## 快速部署（5 分钟）

### 1. 克隆仓库

```bash
git clone https://gitee.com/s7w0k/pr-agent-demo.git
cd pr-agent-demo
```

### 2. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，至少配置 DeepSeek Key 和 JWT 签名密钥：

```ini
# 必填：DeepSeek API Key（https://platform.deepseek.com/api_keys）
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
JWT_SECRET=请替换为至少32字符的随机强密钥
# 生产环境建议设置；留空时 Redis 不启用密码认证
REDIS_PASSWORD=请替换为随机强密码
```

可使用以下任一命令生成密钥：

```bash
openssl rand -hex 32
# 或
python -c "import secrets; print(secrets.token_hex(32))"
```

> `JWT_SECRET` 必须在首次启动前设置，并在同一部署环境中保持稳定。更换该值会使所有已签发 Token 立即失效；严禁提交真实密钥到 Git。

以下可选（不填不影响核心功能）：

| 变量 | 说明 | 不填的影响 |
|------|------|-----------|
| `WEWE_RSS_URL` / `WEWE_AUTH_CODE` | 微信公众号 RSS | 无法爬取公众号文章 |
| `TAVILY_API_KEY` | 已废弃（改用 RSS） | 无影响 |
| `JWT_ALGORITHM` | JWT 签名算法，默认 `HS256` | 使用默认值 |
| `JWT_EXPIRE_HOURS` | 登录有效期，默认 24 小时 | 使用默认值 |
| `REDIS_PASSWORD` | Redis 认证密码，生产环境建议设置 | Redis 仅在 Docker 内部网络无密码运行 |
| `ARQ_MAX_JOBS` | 单个 Worker 最大并发任务数，默认 3 | 使用默认值 |
| `ARQ_JOB_TIMEOUT` | 单任务超时秒数，默认 600 | 使用默认值 |
| `ARQ_MAX_RETRIES` | 失败后的最大重试次数，默认 3 | 使用默认值 |

### 3. 启动所有服务

```bash
docker compose up -d
```

> 首次构建约 3-5 分钟，后续启动约 30 秒。

### 4. 验证

```bash
curl http://localhost:8000/api/health
# 预期: {"ok":true,"status":"healthy",...}

docker compose ps
# mongodb、redis、mcp-crawl、mcp-wewe、backend、backend-worker 均应为 healthy

docker compose exec backend-worker python -m arq worker.WorkerSettings --check
# 预期包含: Health check successful
```

浏览器打开 **http://localhost:8000**，首次进入会显示登录页。选择“注册”创建首个用户，注册后会自动登录并进入仪表盘。

认证后的 REST 请求需要 `Authorization: Bearer <JWT>`；SSE 对话和改稿端点使用 `?token=<JWT>`。网页端会自动处理这两种认证方式。

## 服务架构

| 服务 | 端口 | 说明 |
|------|------|------|
| `backend` | 8000 | FastAPI API + React 前端；创建任务、写入状态并提交 Redis 队列 |
| `backend-worker` | 无宿主机端口 | ARQ 独立执行进程；运行流水线、重试和检查点恢复 |
| `mongodb` | 27017（内部） | 业务数据、任务状态和 LangGraph 检查点持久化 |
| `redis` | 6379（内部） | ARQ 任务队列；启用 AOF 和 `redis_data` 持久卷 |
| `mcp-crawl` | 8101（内部） | 海外安全新闻 RSS 爬虫 |
| `mcp-wewe` | 8100（内部） | 微信公众号 RSS（可选） |

---

## Redis 与 Worker 运行机制

1. `backend` 创建 `pipeline_tasks` 记录，并将任务提交到 Redis；HTTP 请求不会直接执行完整 Agent 流水线。
2. `backend-worker` 从 Redis 获取任务，按 `ARQ_MAX_JOBS` 控制并发，单任务受 `ARQ_JOB_TIMEOUT` 限制。
3. 失败任务最多自动重试 `ARQ_MAX_RETRIES` 次；任务进度和结果持续写入 MongoDB，不依赖 API 或 Worker 进程内存。
4. V2 LangGraph 在节点之间写入 MongoDB 检查点。中断任务可调用 `POST /api/pipeline/tasks/{task_id}/resume` 从最近检查点重新入队。
5. Redis 使用 AOF 和 `redis_data` 卷保存待执行任务；`docker compose down` 不删除数据，只有 `docker compose down -v` 会同时删除 MongoDB 与 Redis 持久卷。

API 和 Worker 使用同一后端镜像。修改 `services/backend/`、`frontend/` 或后端依赖后，必须同时重建两个服务：

```bash
docker compose build backend backend-worker
docker compose up -d backend backend-worker
```

### 用户模板功能升级与分离部署重建

用户模板页面打包在 `backend` 静态前端中，模板解析和版本冻结同时运行于 `backend` 与 `backend-worker`。升级本功能时必须重建这两个服务，但不需要重建独立的 `pr-crawler`：

```powershell
docker compose -p pr-core `
  --env-file .env `
  --env-file deploy/local/.env.core-local `
  -f docker-compose.yml `
  -f deploy/core/docker-compose.remote-crawl.yml `
  -f deploy/local/docker-compose.core-local.yml `
  build backend backend-worker

docker compose -p pr-core `
  --env-file .env `
  --env-file deploy/local/.env.core-local `
  -f docker-compose.yml `
  -f deploy/core/docker-compose.remote-crawl.yml `
  -f deploy/local/docker-compose.core-local.yml `
  up -d --no-deps backend backend-worker
```

重建后验证：

```powershell
docker compose -p pr-core `
  --env-file .env `
  --env-file deploy/local/.env.core-local `
  -f docker-compose.yml `
  -f deploy/core/docker-compose.remote-crawl.yml `
  -f deploy/local/docker-compose.core-local.yml `
  ps backend backend-worker mongodb redis
```

若使用单机默认部署，继续使用 `docker compose build backend backend-worker` 和 `docker compose up -d backend backend-worker` 即可。模板集合和索引由后端启动过程幂等创建，不需要执行手工迁移。

## MongoDB 集合

| 集合 | 说明 | 创建时机 |
|------|------|----------|
| `articles` | 文章数据（含 PR 草稿、修订记录、反馈冗余字段） | 文章入库时 |
| `reports` | V1 PR 报道 | V1 流水线生成 |
| `chat_sessions` | 对话改稿历史 | 改稿 API 调用时 |
| `feedbacks` | 用户反馈记录（1-5 星评分 + 文字 + 标签） | 提交反馈时 |
| `user_activities` | 用户操作记录（下载/改稿/应用修订等） | 用户操作时自动写入 |
| `user_profiles` | 用户风格画像（偏好模板/视角/语气/改稿方向） | 画像构建时 |
| `user_pr_templates` | 每用户当前生效的 PR 模板覆盖 | 首次保存模板时 |
| `user_pr_template_versions` | 每用户不可变模板历史，最多保留 20 版 | 保存、重置或回滚时 |
| `users` | 用户账号和 bcrypt 密码摘要 | 用户注册时 |
| `user_drafts` | 每用户独立的个性化草稿 | 草稿生成时 |
| `pipeline_tasks` | 异步流水线状态、进度和结果 | 触发流水线时 |
| `pipeline_checkpoints` | LangGraph 节点级状态快照 | V2 流水线执行到节点时 |
| `pipeline_checkpoint_writes` | LangGraph 检查点中间写入 | V2 节点执行时 |
| `llm_call_logs` | LLM Schema、降级、Token、耗时和调用归属元数据 | 分类或评分调用 LLM 时 |
| `pipeline_logs` | 每用户独立的流水线日志 | 流水线运行时 |

## 阶段六旧数据迁移

升级前请先备份 MongoDB。旧版 `local-user` 数据不会自动归属新账号；如需保留，请先注册目标用户，并从 `users` 集合取得其 `user_id`：

```bash
docker compose exec mongodb sh -c 'mongosh pr_agent \
  -u "$MONGO_INITDB_ROOT_USERNAME" -p "$MONGO_INITDB_ROOT_PASSWORD" \
  --authenticationDatabase admin \
  --eval "db.users.find({}, {user_id:1, username:1, _id:0}).pretty()"'
```

在 backend 容器内执行迁移：

```bash
docker compose exec backend python scripts/migrate_local_user.py <target_user_id>
```

脚本会迁移 `feedbacks`、`user_activities`、`user_profiles`、`chat_sessions`、`pipeline_logs`，并将旧 `articles.pr_drafts` 写入目标用户的 `user_drafts`。迁移应在停止流水线任务后执行；脚本会校验目标用户存在。

### 索引

后端启动时自动创建以下索引：

```javascript
// feedbacks
db.feedbacks.createIndex({ "feedback_id": 1 }, { unique: true })
db.feedbacks.createIndex({ "user_id": 1, "target_type": 1, "target_ref.article_url_hash": 1 })
db.feedbacks.createIndex({ "created_at": -1 })

// user_activities
db.user_activities.createIndex({ "activity_id": 1 }, { unique: true })
db.user_activities.createIndex({ "user_id": 1, "created_at": -1 })
db.user_activities.createIndex({ "action": 1, "created_at": -1 })

// user_profiles
db.user_profiles.createIndex({ "user_id": 1 }, { unique: true })

// user_pr_templates
db.user_pr_templates.createIndex(
  { "user_id": 1, "template_key": 1 },
  { unique: true, name: "uq_user_template_key" }
)
db.user_pr_templates.createIndex(
  { "user_id": 1, "category_v2": 1, "slot": 1 },
  { unique: true, name: "uq_user_category_slot" }
)

// user_pr_template_versions
db.user_pr_template_versions.createIndex(
  { "user_id": 1, "template_key": 1, "version": 1 },
  { unique: true, name: "uq_user_template_version" }
)
```

## 常用运维命令

```bash
# 查看 API 与 Worker 日志
docker compose logs backend -f --tail 50
docker compose logs backend-worker -f --tail 50

# 重启单个服务
docker compose restart backend
docker compose restart backend-worker

# 检查 Redis 与 Worker 健康状态
docker compose ps redis backend-worker
docker compose exec backend-worker python -m arq worker.WorkerSettings --check

# 停止所有服务
docker compose down

# 更新代码后重建
git pull origin main
docker compose build --no-cache backend backend-worker
docker compose up -d

# 清理所有数据重新开始
docker compose down -v
docker compose up -d
```

## 常见问题

**Q: 启动后页面空白？**

检查日志：`docker compose logs backend | grep "Agent init skipped"`。如果看到此日志，确认 `.env` 中 `DEEPSEEK_API_KEY` 已填。

**Q: backend-worker 显示 unhealthy 或任务一直 pending？**

依次检查 Redis、Worker 心跳和执行日志：

```bash
docker compose ps redis backend-worker
docker compose exec backend-worker python -m arq worker.WorkerSettings --check
docker compose logs backend-worker --tail 100
```

如果修改过 `REDIS_PASSWORD`，必须执行 `docker compose up -d --force-recreate redis backend backend-worker`，确保三个服务使用同一个密码。若仅修改后端代码，需要同时重建 `backend` 与 `backend-worker`。

**Q: 海外新闻爬不到？**

爬虫使用 RSS Feed，无需 API Key。确认 Docker 网络能访问外网：
```bash
docker compose exec mcp-crawl curl -I https://feeds.feedburner.com/TheHackersNews
```

**Q: 微信公众号爬不到？**

需要配置 WeWe RSS 服务地址和认证码。不配置不影响海外新闻和核心流水线。

**Q: 如何更换 LLM 模型？**

修改 `.env` 中的 `DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL`，支持任何 OpenAI 兼容接口。

**Q: 对话改稿功能不工作？**

对话改稿复用 `DEEPSEEK_API_KEY`，无需额外配置。如果改稿返回 502 错误，检查：
1. `DEEPSEEK_API_KEY` 是否有效
2. DeepSeek API 是否可达：`docker compose exec backend curl -I https://api.deepseek.com`
3. 后端日志：`docker compose logs backend --tail 20 | grep -i error`

**Q: 用户画像页面显示"尚未生成"？**

用户画像需要积累一定的反馈数据后才会自动生成。可以：
1. 对草稿进行评分反馈（累计 ≥ 5 条后自动触发画像构建）
2. 在用户画像页面手动点击"重建画像"按钮

**Q: 保存模板提示“模板已被其他会话修改”？**

同一账号的另一个浏览器会话已保存了新版本。关闭编辑抽屉并点击“刷新模板”，基于最新版本重新编辑；不要重复提交旧页面中的内容。

**Q: 保存后流水线仍使用旧模板？**

已入队任务会冻结触发时的模板版本，避免执行中途发生漂移。请新建 V2 流水线或单篇生成任务，并确认 `backend-worker` 已与 `backend` 同时重建。历史草稿不会被自动改写。

**Q: 如何恢复默认或回滚历史版本？**

- “恢复默认”删除当前生效覆盖，立即回退到系统模板，但保留历史快照。
- “历史 -> 恢复此版本”将快照保存成一个更高版本，不覆盖已有历史。
- 两项操作都只作用于当前登录用户。

可用 MongoDB 验证用户隔离和版本：

```bash
docker compose exec mongodb mongosh pr_agent --eval \
  'db.user_pr_templates.find({}, {user_id:1, template_key:1, version:1, name:1, _id:0}).pretty()'
docker compose exec mongodb mongosh pr_agent --eval \
  'db.user_pr_template_versions.find({}, {user_id:1, template_key:1, version:1, change_type:1, _id:0}).sort({version:-1}).limit(20).pretty()'
```

**Q: 反馈和操作记录数据在哪查看？**

通过 API 查看：
- `GET /api/feedback?article_url_hash={hash}` - 查看指定文章的反馈
- `GET /api/activities?page=1&page_size=20` - 查看操作记录
- `GET /api/activities/stats?days=30` - 查看 30 天操作统计

或直接查询 MongoDB：
```bash
docker compose exec mongodb mongosh pr_agent --eval "db.feedbacks.find().limit(5).pretty()"
docker compose exec mongodb mongosh pr_agent --eval "db.user_activities.find().limit(5).pretty()"
docker compose exec mongodb mongosh pr_agent --eval "db.user_profiles.find().pretty()"
```
