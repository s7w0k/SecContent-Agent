# 产品知识库管理指南

## 1. 概述

产品知识库是 PR Agent 系统的核心知识源，存放于 `agent-security-briefs/` 目录下的 Markdown 文件。系统提供可视化页面用于浏览、编辑、校验和发布知识库内容。

**访问路径**：登录后进入「配置 -> 产品知识库」

## 2. 权限说明

| 角色 | 权限 |
|------|------|
| 普通用户 | 浏览目录树、查看 Markdown 正文、搜索文件 |
| 管理员 (`is_admin=true`) | 以上 + 创建草稿、校验、Prompt 预览、试打分、发布、回滚 |
| 开发者 (`is_developer=true`) | 开发者权限不自动获得知识管理权限 |

设置管理员权限：
```bash
docker compose exec backend python scripts/set_admin.py <username>
```

## 3. 浏览知识库

1. 进入「配置 -> 产品知识库」页面。
2. 左侧显示真实目录树，点击文件节点查看内容。
3. 顶部状态卡片展示知识哈希、加载时间和文件统计。
4. 搜索栏支持按文件名和正文子串搜索。
5. 每个文件标注用途角色（产品事实、市场简报、角色工作流等）和评分参与状态。

## 4. 编辑草稿

1. 管理员在文件查看器中点击「创建草稿」按钮。
2. 系统读取当前正式文件内容作为草稿初始版本。
3. 在编辑器中修改 Markdown 内容。
4. 填写变更摘要，点击「保存草稿」。
5. 草稿保存在 MongoDB，**不修改正式文件**。
6. 同一文件只允许一个编辑中草稿。

## 5. 校验与预览

### 5.1 格式校验

点击「校验」标签页中的「运行校验」按钮：
- 检查内容非空、无 NUL 字符。
- 核心打分文件必须包含 Markdown 标题。
- 使用临时 KnowledgeLoader 验证加载。
- 非直接打分文件会提示「V2 Prompt 可能不变」。

### 5.2 Prompt 预览

点击「Prompt 预览」标签页：
- 对比新旧打分 Prompt 的 SHA-256 哈希。
- 展示字符数变化。
- 并排显示新旧 Prompt 文本。

### 5.3 试打分

点击「试打分」标签页：
1. 填写测试文章信息（标题、来源、分类、摘要、正文）。
2. 系统会显示 **LLM 费用警告**。
3. 点击「运行试打分」，系统分别用正式知识和草稿知识对文章评分。
4. 对比新旧评分差异（product_relevance、event_impact、pr_total_score）。

## 6. 发布

1. 确认草稿已校验通过。
2. 点击「发布」按钮。
3. 填写版本名称（如 `KB-2026.07.1`）和发布说明。
4. 系统执行：
   - 获取全局发布锁。
   - 乐观哈希冲突检测（如果文件已被其他人修改，返回 409）。
   - 保存旧内容快照到 MongoDB。
   - 原子写入正式文件（`os.replace`）。
   - 验证新知识加载正常。
   - 标记草稿为已发布。
5. 发布成功后：
   - API 进程立即刷新知识缓存。
   - Worker 在下一个任务开始前检测文件变更。
   - 正在执行的任务使用旧知识完成。

## 7. 回滚

1. 在发布历史中找到目标版本。
2. 点击「回滚」按钮。
3. 填写回滚原因。
4. 系统从 MongoDB 修订记录中恢复旧内容。
5. 回滚也创建新的发布记录（不删除原历史）。

## 8. 核心文件保护

以下 5 个文件直接参与 V2 打分 Prompt 拼接，允许编辑内容但**禁止重命名、移动和删除**：

```
1-智能体身份安全/overview.md
1-智能体身份安全/market-brief.md
3-AI-BOM/overview.md
3-AI-BOM/market-brief.md
shared/hot-event-playbook.md
```

以下目录第一版只读，不允许编辑：
- `_index/` - 文件夹路由
- `skills/` - 角色工作流
- `原始文档/` - 原始资料

## 9. Docker 部署说明

### 卷挂载

```yaml
backend:
  volumes:
    - ./agent-security-briefs:/app/documents:rw   # 读写

backend-worker:
  volumes:
    - ./agent-security-briefs:/app/documents:ro   # 只读
```

- API 容器需要写权限以发布知识更新。
- Worker 保持只读，通过文件哈希检测变更。
- 两个容器共享同一个宿主机目录。

### 备份策略

同时备份以下两部分：
1. `agent-security-briefs/` 目录（正式知识文件）。
2. MongoDB 数据库（草稿、发布历史、修订记录、审计日志）。

## 10. 常见问题

### Q: 两个管理员同时编辑同一文件会怎样？
A: 草稿各自独立。发布时执行乐观哈希冲突检测，后发布者会收到 409 错误，需重新载入正式内容后合并。

### Q: 发布后评分没有变化？
A: 如果修改的不是 5 个核心打分文件之一，V2 Prompt 不会变化。页面会提示「此文件不直接参与 V2 打分 Prompt」。

### Q: 发布失败后文件会怎样？
A: 系统自动恢复所有已写入的文件到发布前状态，发布记录标记为 failed。

### Q: Worker 什么时候使用新知识？
A: Worker 在每个新任务开始前检测文件哈希变更。正在执行的任务使用旧知识完成，不会中途切换。

### Q: 草稿会影响评分吗？
A: 不会。草稿只存储在 MongoDB 中，不写入正式目录。只有发布后才影响评分。
