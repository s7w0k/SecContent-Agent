## 1. 整体目标与交付物

## 2. 团队开发规范

### 2.1 Git 分支策略（Trunk-Based）

```
main          ← 始终可部署（受保护，禁止直推）
  ├── release/0.1.0   ← 阶段发布分支
  └── feat/*          ← 功能分支，从 main 拉，PR 合回 main
       └── feat/1.1-project-scaffold
       └── feat/1.2-mcp-crawl
       └── feat/1.3-mongodb-models
       └── feat/1.4-docker-base
```

**规则**:
- `main` 分支受保护：需 1 人审查 + CI 通过方可合并
- 功能分支命名：`feat/<任务编号>-<简短描述>`
- 禁止 `git push --force` 到 `main`
- 每个 PR 粒度 ≤ 300 行变更（便于审查）
- 所有提交必须在 Gitee PR 页面进行 Code Review

### 2.2 Commit 规范（Conventional Commits）

```
<type>(<scope>): <description>

[optional body]

[optional footer]
```

| Type | 用途 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `refactor` | 重构（不改变行为） |
| `test` | 测试 |
| `docs` | 文档 |
| `chore` | 构建/工具/依赖 |
| `ci` | CI/CD 配置 |
| `perf` | 性能优化 |

**示例**:
```
feat(mcp-crawl): implement crawl_news MCP tool with tavily integration
fix(backend): resolve MongoDB connection leak in lifespan handler
chore(docker): add healthcheck to all service containers
```

### 2.3 Code Review 检查清单

每份 PR 至少检查以下项目：

- [ ] 是否引入了硬编码密钥
- [ ] 异常处理是否充分（无裸 `except:`）
- [ ] 日志是否使用 `logging` 模块（非 `print`）
- [ ] 是否有对应的单元测试
- [ ] 环境变量是否已加入 `.env.example`
- [ ] 依赖是否最小化（无未使用的 import）
- [ ] Dockerfile 是否使用 multi-stage build 减小镜像

## 3. 安全边界与分析

### 3.1 安全域划分

```
┌─────────────────────────────────────────────────────────────┐
│                      Docker Network Boundary                │
│                                                             │
│  ┌──────────────────────────────────┐                       │
│  │   External Network (host)        │                       │
│  │   Port: 8000 (backend)           │  ← 用户浏览器访问      │
│  └────────────┬─────────────────────┘                       │
│               │                                             │
│  ┌────────────▼─────────────────────┐                       │
│  │   Internal Network (agent-net)   │                       │
│  │   subnet: 172.28.0.0/16          │                       │
│  │                                  │                       │
│  │  ┌──────────┐  ┌──────────┐     │                       │
│  │  │ mcp-wewe │  │mcp-crawl │     │                       │
│  │  │  :8100   │  │  :8101   │     │  ← 不暴露到宿主机      │
│  │  └────┬─────┘  └────┬─────┘     │                       │
│  │       │              │           │                       │
│  │       └──────┬───────┘           │                       │
│  │              │                   │                       │
│  │  ┌──────────▼──────────┐         │                       │
│  │  │      backend        │         │                       │
│  │  │       :8000         │         │  ← API 网关            │
│  │  └──────────┬──────────┘         │                       │
│  │             │                    │                       │
│  │  ┌──────────▼──────────┐         │                       │
│  │  │      mongodb        │         │                       │
│  │  │       :27017        │         │  ← 不暴露到宿主机      │
│  │  └─────────────────────┘         │                       │
│  └──────────────────────────────────┘                       │
└─────────────────────────────────────────────────────────────┘
```

**网络安全策略**:
- 仅 `backend:8000` 映射到宿主机（用户入口）
- `mcp-wewe:8100` / `mcp-crawl:8101` / `mongodb:27017` 仅内部网络可达
- 服务间通信通过 Docker DNS 解析容器名（如 `http://mcp-wewe:8100`）
- 禁止 `network_mode: host`

### 3.2 密钥与敏感信息管理

| 密钥 | 使用者 | 风险等级 | 管理策略 |
|------|--------|----------|----------|
| `DEEPSEEK_API_KEY` | 所有服务 | **高** | 仅通过 `.env` 注入，不入仓 |
| `TAVILY_API_KEY` | mcp-crawl | **高** | 仅通过 `.env` 注入，不入仓 |
| `WEWE_RSS_URL` | mcp-wewe | **中** | 内网地址，`.env` 管理 |
| `WEWE_AUTH_CODE` | mcp-wewe | **高** | 仅通过 `.env` 注入，不入仓 |
| `MONGODB_URI` | backend | **中** | `mongodb://admin:pass@mongodb:27017`，`.env` 管理 |

**密钥防护措施**:

1. **`.gitignore` 白名单制** — 默认忽略所有 `.env*`，仅放行 `.env.example`
2. **Pre-commit Hook** — 使用 `detect-secrets` 或 `gitleaks` 扫描，阻止密钥入仓
3. **CI 密钥注入** — 通过 Gitee CI Secrets 变量注入，不在配置文件中写死
4. **Docker Secret 备选** — 生产部署时考虑 Docker Secret / Vault 方案
5. **密钥轮换** — API Key 每季度轮换，CI 流水线自动通知过期

### 3.3 依赖安全

```yaml
# 阶段一引入的安全扫描
工具链:
  依赖漏洞: pip-audit (Python) / npm audit (Node.js)
  SAST:     bandit (Python) / eslint-plugin-security (JS)
  镜像扫描: docker scout / trivy
```

### 3.4 最小权限原则（容器运行时）

每个容器的 `docker-compose.yml` 安全配置：

```yaml
services:
  backend:
    security_opt:
      - no-new-privileges:true
    read_only: true              # 文件系统只读（除 tmp）
    tmpfs:
      - /tmp
    cap_drop:
      - ALL                      # 去除所有 Linux capabilities
    cap_add:
      - NET_BIND_SERVICE         # 仅保留端口绑定
```

### 3.5 输入边界校验

阶段一就需要建立的输入校验层：

```
外部请求 → FastAPI pydantic 校验 → Service 层 → MongoDB（参数化查询）
         ├─ URL 白名单校验（防 SSRF）
         ├─ 请求体大小限制（防 DoS）
         └─ 分页参数上下界（防遍历）
```

## 4. CI/CD 流水线设计

### 4.1 整体流水线架构

```
Gitee Push / PR
     │
     ▼
┌─────────────┐
│  Lint 阶段   │  ruff + biome + hadolint         并行  ~30s
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Test 阶段   │  pytest + vitest                  并行  ~2min
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Build 阶段  │  docker build 各服务镜像            并行  ~3min
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Scan 阶段   │  trivy 镜像漏洞扫描 + bandit SAST   并行  ~2min
└──────┬──────┘
       │ (仅 main 分支)
       ▼
┌─────────────┐
│  Release    │  docker tag + push to registry    手动触发
└─────────────┘
```

### 4.2 Gitee CI 配置（`.gitee/workflows/ci.yml`）

```yaml
name: CI Pipeline

on:
  push:
    branches: [main, 'feat/*']
  pull_request:
    branches: [main]

jobs:
  lint-python:
    runs-on: ubuntu-latest
    container: python:3.12-slim
    steps:
      - uses: actions/checkout@v4
      - run: pip install ruff
      - run: ruff check services/
      - run: ruff format --check services/

  lint-frontend:
    runs-on: ubuntu-latest
    container: node:22-alpine
    steps:
      - uses: actions/checkout@v4
      - run: cd frontend && npm ci && npx biome ci .

  lint-docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hadolint/hadolint-action@v3

  test-python:
    needs: [lint-python]
    runs-on: ubuntu-latest
    services:
      mongodb:
        image: mongo:7
    steps:
      - uses: actions/checkout@v4
      - run: pip install -r services/backend/requirements.txt
      - run: pip install -r services/mcp_crawl/requirements.txt
      - run: pip install pytest pytest-asyncio pytest-cov httpx
      - run: pytest tests/ --cov=services --cov-report=xml
      - uses: codecov/codecov-action@v4

  test-frontend:
    needs: [lint-frontend]
    runs-on: ubuntu-latest
    container: node:22-alpine
    steps:
      - uses: actions/checkout@v4
      - run: cd frontend && npm ci && npx vitest run

  build:
    needs: [test-python, test-frontend]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker compose build

  security-scan:
    needs: [build]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install bandit && bandit -r services/ -f json -o bandit-report.json
      - run: docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy image --severity HIGH,CRITICAL pr-agent-backend:latest
```

## 5. 测试策略

### 5.1 测试金字塔（阶段一）

```
         ╱  E2E ╲          ← 阶段一暂不涉及（阶段四引入）
        ╱────────╲
       ╱ Integration ╲     ← API 契约测试 / Docker 服务联通测试
      ╱──────────────╲
     ╱   Unit Tests    ╲   ← 模型 / 工具函数 / 配置解析
    ╱──────────────────╲
```

### 5.2 阶段一测试覆盖范围

| 被测对象 | 测试类型 | 测试框架 | 关键测试点 |
|----------|----------|----------|------------|
| `mcp_crawl/server.py` | 单元 | pytest + pytest-asyncio | 每个 MCP 工具函数可独立调用 |
| `mcp_crawl/http_bridge.py` | 集成 | pytest + httpx | `/tools` 端点返回正确工具列表 |
| `backend/config.py` | 单元 | pytest | 环境变量解析、默认值、缺失必填抛异常 |
| `backend/db/mongo.py` | 集成 | pytest + mongomock | 连接建立、CRUD 操作 |
| `backend/models/` | 单元 | pytest | Beanie/ODM 模型校验、字段类型 |
| `mongodb/init.js` | 集成 | pytest | 容器启动后索引存在 |
| `docker-compose.yml` | 冒烟 | shell | `docker compose up` 所有容器 healthy |

```python
# services/backend/db/mongo.py
from motor.motor_asyncio import AsyncIOMotorClient, AsyncIOMotorDatabase
from pymongo.errors import ConnectionFailure
import logging

logger = logging.getLogger(__name__)

class MongoDB:
    """MongoDB 连接管理器（单例）"""
    client: AsyncIOMotorClient | None = None
    db: AsyncIOMotorDatabase | None = None

    @classmethod
    async def connect(cls, uri: str, db_name: str = "pr_agent") -> None:
        """建立连接，带重试和超时"""
        cls.client = AsyncIOMotorClient(
            uri,
            serverSelectionTimeoutMS=5000,
            connectTimeoutMS=5000,
            maxPoolSize=20,
            minPoolSize=2,
        )
        try:
            await cls.client.admin.command("ping")
        except ConnectionFailure as e:
            logger.error(f"MongoDB connection failed: {e}")
            raise
        cls.db = cls.client[db_name]
        logger.info(f"MongoDB connected: {db_name}")

    @classmethod
    async def disconnect(cls) -> None:
        if cls.client:
            cls.client.close()
            logger.info("MongoDB disconnected")

    @classmethod
    def get_db(cls) -> AsyncIOMotorDatabase:
        if cls.db is None:
            raise RuntimeError("MongoDB not initialized. Call connect() first.")
        return cls.db
```
